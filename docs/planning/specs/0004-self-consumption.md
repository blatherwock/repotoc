# Spec: self-consumption

## Objective

repotoc consumes the pre-commit hook it ships: this repository's own artifact is regenerated by `repotoc` on commit, gated read-only by `just check`, and tracked in git. The change wires the repository to use itself exactly as consumers do. It requires the delivery surface (`0003-delivery-surface.md`), which is complete.

## Requirements

The hook runs in the zero-argument, config-driven form 0003 defines as the intended pre-commit form. A `[tool.repotoc]` section in `pyproject.toml` sets `sources = ["src", "tests"]`; no CLI flags or hook overrides appear in the wiring.

`.pre-commit-config.yaml` references this repository by local path (`repo: ./`) with `rev: HEAD`, consuming the shipped `.pre-commit-hooks.yaml` verbatim: `entry: repotoc`, `language: python`, `pass_filenames: false`, `files: (\.py$|^pyproject\.toml$)`. The hook environment is managed by pre-commit; the repository adds no dependency on it.

The same config pins `default_language_version: python: python3.14`: pre-commit never reads `.python-version` and resolves the default interpreter by PATH lookup, which can land on an old host python. Host setup runs `uv python install 3.14`, which links `python3.14` into `~/.local/bin` where the pin finds it.

The generated `docs/repotoc` artifact is tracked in git. Enforcement depends on it: pre-commit fails only when a tracked file is modified [confirmed], and `--check` staleness presumes committed output.

`just check` ends with a freshness gate, `uv run repotoc --check`: exit 0 when fresh, exit 1 with the stale file list when not (0003). Its outcome matches the host hook's: a commit is blocked while the artifact is stale, the gate fails while it is stale. `just fix` runs generate mode, `uv run repotoc`, as the gate's write counterpart: it rewrites the rendered file set and prunes extra `.md` files under the output directory, clearing every staleness class the gate can report.

pre-commit itself is installed outside the repository, globally on the host; a `just` recipe runs `pre-commit install` for host setup, and host setup also installs the pinned interpreter with `uv python install 3.14`.

## Decisions

- **Self-consume via `repo: ./` with `rev: HEAD`.** pre-commit installs this repository from its own path and reads the hook definition we ship to consumers, so the self-hosted wiring and the consumer wiring cannot diverge. The environment is pre-commit-managed; committing needs no uv and no activated venv on the host. Verified end to end in a scratch repository: generation, the tracked-file failure, and live source pickup [confirmed]. Rejected: a `repo: local` hook with `entry: uv run repotoc` and `language: system` (requires uv wherever pre-commit runs, the requirement 0003 rejected for consumers, a fortiori for this repository) and a `repo: local` hook with `language: python` plus `additional_dependencies` (cannot reference the local project cleanly).
- **`rev: HEAD` despite the mutable-reference warning.** pre-commit warns that mutable references are never updated after first install [confirmed]. Irrelevant here: with a local-path repository the hook environment picks up working-tree changes without a rebuild, verified by editing source and rerunning [confirmed]. The warning is cosmetic; a comment in the config says so.
- **Pin `default_language_version` to `python3.14`.** pre-commit resolves the default interpreter by PATH lookup (`python3.<its own minor>`, then `python3`) and never reads `.python-version`; on the host it landed on python 3.9 [confirmed], below the package floor of 3.11. The pin names the interpreter that `uv python install 3.14` links into `~/.local/bin`, so the hook env matches the python uv manages for the project. Verified: the hook env builds as `py_env-python3.14` on 3.14.8 [confirmed]. Rejected: relying on default resolution alone (implicit, breaks silently when pre-commit's own interpreter or PATH changes) and pinning an absolute interpreter path (host-specific, not committable).
- **The artifact is tracked.** Untracked artifact files never trigger the "files were modified" failure [confirmed], so until the first artifact commit the hook enforces nothing; this change commits the initial artifact itself. Rejected: gitignoring the artifact (enforcement and staleness detection both disappear).
- **Scope is `src` and `tests`.** Self-documentation covers the whole repository, so both source roots feed the artifact.
- **pre-commit lives outside the repository.** The host installs it globally (uv tool) and runs `pre-commit install`; the repository ships only `.pre-commit-config.yaml`. Rejected: a dev dependency group entry (duplicates the host global install, and the container runs never use it).
- **`just check` parity via `uv run repotoc --check`.** The container gate cannot run pre-commit against the read-only `.git` mount, so the gate runs the read-only equivalent of the hook's regenerate mode; both share 0003's exit semantics, so gate and hook agree on freshness without the container needing pre-commit.

## Testing strategy

The wiring is repository configuration, not package code. Scenarios are verified by inspection and by command in the container; the hook's commit-time behavior is verified once on the host at setup time. The package suite is untouched; its coverage gate still applies to any touched package code (none expected).

### Hook: normal operation

- When a commit stages tracked `*.py` or `pyproject.toml` changes, the hook regenerates `docs/repotoc` from config alone.
- When regeneration changes a tracked artifact file, the hook fails with "files were modified by this hook"; after re-staging the artifact, the same commit passes.
- When the staged changes leave the artifact unchanged, the hook passes.

### Hook: failure handling

- When the run hits a config, filesystem, or parse error, the hook fails with the exit-2 message on stderr (0003).
- When no staged file matches `(\.py$|^pyproject\.toml$)`, the hook does not run.

### Hook: edge cases

- When repotoc's own source changes in the working tree, the next hook run reflects the change without an environment rebuild [confirmed].
- When the hook environment builds on a host whose PATH `python3` is older than the package floor, the pinned `python3.14` linked by `uv python install 3.14` is used instead [confirmed].
- While the artifact holds untracked files, modifying them does not fail the hook [confirmed]; enforcement begins at the initial artifact commit.
- Each run prints the mutable-reference warning; it does not affect behavior.

### Freshness gate (`just check`)

- When `just check` runs with a fresh artifact, `repotoc --check` exits 0 and the gate passes.
- When the artifact is stale, `repotoc --check` exits 1 listing missing, differing, and extra files, and `just check` fails.
- When an artifact file is hand-edited in a docs-only commit (no `.py` file staged, so the hook does not run), the gate still reports the file as stale.

## Out of scope

- CI wiring for the hook or the gate; no current document owns CI.
- Pre-commit running other tools (ruff, ty); `just check` remains the definition-of-done gate for those.
- Consumer-facing documentation beyond what 0003 and `.pre-commit-hooks.yaml` already state.
