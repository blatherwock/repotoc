# Implementation plan: showcase structure view

## Overview

Reworks the showcase from `docs/planning/specs/0006-showcase-site.md`. Today one output pane switches between a module doc file and the root index, which makes the panel do two jobs, and it never shows that the doc tree mirrors the source tree. The showcase splits into two steps, each reading input to output:

1. Structure: three columns. The fixture source tree, the doc tree RepoTOC writes for it, and the rendered `fixture/arcade/repotoc_toc.md`. One toggle above sets the index depth: 6 (the default, the whole tree) or 2 (a targeted index).
2. One module: the current split, `minimax.py` beside `minimax.md`, with the signatures, privates, and member depth toggles. The view switch goes away.

Decisions (confirmed with the user):

- The trees are generated by `src/tools/site_build.py` and gated like the other blocks, so they cannot drift from the fixture.
- Both trees are rooted at `fixture/arcade/`. Fixed collapse rules fold `pong/` and `players/strategies/` to one line each, keeping each tree near twelve lines. `minimax.py` and `minimax.md` are highlighted to tie into step 2.
- The doc tree is derived from the source tree by name mapping (`__init__.py` to `repotoc_toc.md`, `x.py` to `x.md`), so its rows line up with the source rows. Each mapped path must exist in the generated output, or the build fails.
- The index sample is `fixture/arcade/repotoc_toc.md`, not the output root: the root index heading is the variant directory name (`generated/toc-6`) and its first level is a lone `fixture/` entry, both noise for a reader.
- The index depths are 6 and 2, replacing 6 and 1. At the `arcade` level, depth 2 lists each game's direct contents only; depth 1 at the root showed a single line.
- The doc tree pane head reads `docs/repotoc/fixture/arcade/` (the default output directory), not the variant path. The head is hand-written, outside the marked blocks.

The doc tree is built by mapping source names rather than listing the output directory. Collapse paths and highlight paths are module constants beside `FIXTURE_SOURCE`.
